# Step 15 - W25Q SPI NOR driver interface

## What we are solving
Persistent storage for readings (and later the Project 2 event log) on a W25Q NOR flash
that shares SPI2 with the ENC28J60.

## Why
- The bus layer from step 05 already serialises the two chips; the W25Q only needs its
  own chip select (PB1) and its command set.
- NOR flash rules shape the API: erase is per 4 KB sector (bits go 0 -> 1 only by erase),
  program is per 256-byte page (bits go 1 -> 0), every program/erase needs WRITE ENABLE and
  ends with a BUSY poll. Getting these wrong corrupts data silently, so the contract is in
  `w25q.h` before the code.
- The probe (JEDEC ID) is given so the board reports what it found; the data path is
  yours to write and verify on the logic analyser.

## What changed
- `drivers/w25q/w25q.c/.h` - command set, `w25q_init()` (release power-down, JEDEC ID,
  capacity from byte 3), `w25q_read_status()`, `w25q_wait_ready()`.
  **Mentee task:** `w25q_read()`, `w25q_page_program()`, `w25q_sector_erase()`; they
  return `W25Q_ERR_NOT_READY` until implemented.
- `app/main.c` - probe at boot. `app/log/log.h` - `w25q` module.

## How to verify
```
.\build.ps1 clean all
```
Console without a flash chip:
```
[W][w25q] not present (JEDEC FFFFFF)
```
With a W25Q64 on PB1/PB13-15:
```
[I][w25q] JEDEC EF4017, 8192 KB
```
Mentee checks after implementing the bodies: erase sector 0, read 16 bytes (all FFh),
program "eco" at address 0, read it back; capture the 03h and 02h transactions.
